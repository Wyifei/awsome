# SHARA 智能体工作流详解

> **SHARA**: Security Hub Auto-Remediation Agent

## 1. 智能体架构概览

SHARA 系统包含三个核心 Agent，基于 Strands SDK + AWS Bedrock AgentCore 构建：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        SHARA Agent Architecture                             │
│                                                                             │
│   Phase 1 (Pre-Approval)           Phase 2 (Post-Approval)                  │
│   ┌─────────────────────┐          ┌─────────────────────────────────────┐  │
│   │                     │          │                                     │  │
│   │  ┌───────────────┐  │          │  ┌───────────────┐  ┌────────────┐  │  │
│   │  │   Analyzer    │  │          │  │  Remediator   │──│ Validator  │  │  │
│   │  │    Agent      │  │   ───▶   │  │    Agent      │  │   Agent    │  │  │
│   │  └───────┬───────┘  │ Approval │  └───────┬───────┘  └─────┬──────┘  │  │
│   │          │          │          │          │     A2A        │         │  │
│   └──────────┼──────────┘          └──────────┼────────────────┼─────────┘  │
│              │                                │                │            │
│              ▼                                ▼                ▼            │
│   ┌──────────────────────────────────────────────────────────────────────┐  │
│   │                     AgentCore Memory                                 │  │
│   │   ┌────────────────────────────┐  ┌─────────────────────────────┐   │  │
│   │   │           STM              │  │            LTM              │   │  │
│   │   │   (Short-Term Memory)      │  │   (Long-Term Memory)        │   │  │
│   │   │   ─────────────────────    │  │   ──────────────────────    │   │  │
│   │   │   • phase1_analysis        │  │   • Episodes (执行记录)     │   │  │
│   │   │   • rollback_data          │  │   • Reflections (方法论)    │   │  │
│   │   │   • remediation_result     │  │                             │   │  │
│   │   └────────────────────────────┘  └─────────────────────────────┘   │  │
│   └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Agent 详细工作流

### 2.1 Analyzer Agent (分析智能体)

**触发**: Event Handler Lambda 调用
**职责**: 分析 Finding，生成修复方案描述（不生成代码）

#### 工具调用流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Analyzer Agent Workflow                              │
│                                                                             │
│  Input: Finding (from Security Hub)                                         │
│                                                                             │
│  Step 1: get_resource_config ─────────────────────────────────────────────┐ │
│  │  • 调用 AWS API 获取资源当前配置                                        │ │
│  │  • 验证资源是否存在                                                      │ │
│  │  • 提取资源类型、ARN、配置详情                                           │ │
│  └─────────────────────────────────────────────────────────────────────────┘ │
│                              │                                              │
│                              ▼                                              │
│  Step 2: fetch_asr_playbook ───────────────────────────────────────────────┐│
│  │  • 从 S3 获取 ASR (Automated Security Response) Playbook               ││
│  │  • 根据 Control ID (如 S3.1) 精确匹配                                   ││
│  │  • 返回预定义的修复描述和代码模板                                        ││
│  │                                                                         ││
│  │  S3 结构:                                                               ││
│  │  s3://bucket/                                                           ││
│  │  ├── index.json                   # Control ID 索引                     ││
│  │  └── playbooks/                                                         ││
│  │      └── {control_id}/                                                  ││
│  │          ├── playbook.json        # 修复描述                            ││
│  │          └── code.py              # 代码模板                            ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 3: search_similar_findings ──────────────────────────────────────────┐│
│  │  • 搜索 AgentCore Memory LTM                                            ││
│  │  • 语义搜索相似的历史修复经验                                            ││
│  │  • 返回 Episodes (具体执行记录) 和 Reflections (方法论)                 ││
│  │                                                                         ││
│  │  LTM 命名空间: /remediation/actors/{accountId}/                         ││
│  │  最小相关度: Episodes=0.35, Reflections=0.5                             ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 4: save_analysis_result ─────────────────────────────────────────────┐│
│  │  • 保存分析结果到 Memory STM                                            ││
│  │  • 数据包含:                                                            ││
│  │    - finding: 原始 Finding                                              ││
│  │    - resource_config: 资源当前配置                                      ││
│  │    - asr_playbook: ASR 匹配结果                                         ││
│  │    - similar_experiences: 历史经验                                      ││
│  │    - remediation_description: 修复方案描述                              ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Output: Analysis Result (JSON)                                             │
│  ─────────────────────────────                                              │
│  {                                                                          │
│    "analysis": { "risk_level": "high", "resource_state": {...} },          │
│    "asr_match": { "confidence": 1.0, "playbook": {...} },                  │
│    "similar_experiences": [...],                                            │
│    "remediation": {                                                         │
│      "description": "修复方案文字描述",                                     │
│      "prerequisites": [...],                                                │
│      "agent_actions": [...],                                                │
│      "post_actions": [...]                                                  │
│    }                                                                        │
│  }                                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 Remediator Agent (修复智能体)

**触发**: Approval Handler Lambda 调用（用户审批后）
**职责**: 生成修复代码，执行修复，调用 Validator 验证

#### 工具调用流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       Remediator Agent Workflow                             │
│                                                                             │
│  Input: task_id, resource_arn, is_rollback (from Approval Handler)          │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────────┐│
│  │ Normal Remediation (is_rollback=false)                                  ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                                                                             │
│  Step 1: get_analysis_context ─────────────────────────────────────────────┐│
│  │  • 从 Memory STM 获取 Phase 1 分析结果                                   ││
│  │  • 包含: finding, resource_config, asr_playbook, similar_experiences    ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 2: get_resource_config ──────────────────────────────────────────────┐│
│  │  • 获取资源最新状态作为 pre_state                                        ││
│  │  • 用于生成回滚代码的基准                                                ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 3: [LLM 生成代码] ───────────────────────────────────────────────────┐│
│  │  • 生成 Python/Boto3 修复代码                                           ││
│  │  • 优先使用 ASR Playbook 模板                                           ││
│  │  • 参考历史经验中的代码模式                                              ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 4: [LLM 生成回滚代码] ───────────────────────────────────────────────┐│
│  │  • 基于 pre_state 生成回滚代码                                          ││
│  │  • 确保能恢复到修复前状态                                                ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 5: save_rollback_to_memory ──────────────────────────────────────────┐│
│  │  ⚠️ 必须在执行前保存回滚数据！                                           ││
│  │  • 保存 pre_state 和 rollback_code 到 Memory STM                        ││
│  │  • 用于后续用户回滚操作                                                  ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 6: pre_execution_check ──────────────────────────────────────────────┐│
│  │  • 快速代码安全检查                                                      ││
│  │  • 检测危险模式: bucket 删除、实例终止、IAM 创建等                       ││
│  │  • 检测凭证泄露: AWS 密钥、私钥等                                        ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 7: execute_code ─────────────────────────────────────────────────────┐│
│  │  • 在 AgentCore Code Interpreter 沙盒中执行                             ││
│  │  • 支持 Session 复用 (重试时)                                           ││
│  │  • 最多重试 2 次                                                        ││
│  │                                                                         ││
│  │  Session 管理:                                                          ││
│  │  ┌─────────────────────────────────────────────────────────────────┐    ││
│  │  │ execute_code(code, close_session=False) ──▶ 保持 session 打开   │    ││
│  │  │ execute_code(code, session_id="xxx")    ──▶ 复用已有 session    │    ││
│  │  │ execute_code(code, close_session=True)  ──▶ 执行后关闭 session  │    ││
│  │  └─────────────────────────────────────────────────────────────────┘    ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 8: save_remediation_result ──────────────────────────────────────────┐│
│  │  • 保存生成的代码和执行结果到 Memory STM                                 ││
│  │  • 供 Validator Agent 读取                                              ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 9: invoke_validator_agent ───────────────────────────────────────────┐│
│  │  • A2A (Agent-to-Agent) 调用 Validator                                  ││
│  │  • 使用 bedrock-agentcore invoke_agent_runtime API                      ││
│  │  • 传递: task_id, resource_arn, is_rollback=false                       ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────────┐│
│  │ Rollback Operation (is_rollback=true)                                   ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                                                                             │
│  Step 1: get_rollback_from_memory ─────────────────────────────────────────┐│
│  │  • 从 Memory STM 获取预存的回滚数据                                      ││
│  │  • 包含: pre_state, rollback_code                                       ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 2: execute_code (rollback) ──────────────────────────────────────────┐│
│  │  • 执行预存的回滚代码                                                    ││
│  │  • 不需要 LLM 重新生成                                                   ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 3: invoke_validator_agent ───────────────────────────────────────────┐│
│  │  • A2A 调用 Validator                                                   ││
│  │  • 传递: task_id, resource_arn, is_rollback=true                        ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.3 Validator Agent (验证智能体)

**触发**: Remediator Agent 通过 A2A 调用
**职责**: 验证修复结果，更新 Security Hub，保存经验

#### 工具调用流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Validator Agent Workflow                             │
│                                                                             │
│  Input: task_id, resource_arn, is_rollback (from A2A)                       │
│                                                                             │
│  Step 1: get_remediation_result ───────────────────────────────────────────┐│
│  │  • 从 Memory STM 获取代码和执行结果                                      ││
│  │  • 包含: generated_code, execution_result                               ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 2: review_code_security ─────────────────────────────────────────────┐│
│  │  • LLM 全面代码安全审查                                                  ││
│  │  • 分析潜在风险和安全问题                                                ││
│  │  • 输出风险等级: low / medium / high                                    ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 3: verify_resource_state ────────────────────────────────────────────┐│
│  │                                                                         ││
│  │  if is_rollback == false:                                               ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ 验证资源已达到安全配置                                               │ ││
│  │  │ • 根据 Control ID 检查对应的安全要求                                 │ ││
│  │  │ • 例: S3.1 检查 Block Public Access 是否启用                        │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  │                                                                         ││
│  │  if is_rollback == true:                                                ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ 验证资源已恢复到 pre_state                                           │ ││
│  │  │ • 从 Memory 获取 pre_state                                          │ ││
│  │  │ • 对比当前状态与 pre_state                                           │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 4: update_security_hub_finding ──────────────────────────────────────┐│
│  │                                                                         ││
│  │  if is_rollback == false && verification_passed:                        ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ Finding Workflow Status → RESOLVED                                  │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  │                                                                         ││
│  │  if is_rollback == true && verification_passed:                         ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ Finding Workflow Status → NEW                                       │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 5: save_experience_to_ltm ───────────────────────────────────────────┐│
│  │                                                                         ││
│  │  ⚠️ 仅在修复成功时保存 (is_rollback=false)                               ││
│  │                                                                         ││
│  │  保存内容:                                                              ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ Episode (执行记录):                                                  │ ││
│  │  │ • control_id                                                        │ ││
│  │  │ • resource_type                                                     │ ││
│  │  │ • generated_code                                                    │ ││
│  │  │ • execution_result                                                  │ ││
│  │  │ • timestamp                                                         │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  │                                                                         ││
│  │  回滚操作不保存经验 (避免污染 LTM)                                       ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                              │                                              │
│                              ▼                                              │
│  Step 6: trigger_result_email ─────────────────────────────────────────────┐│
│  │  • 调用 Lambda 发送结果邮件                                              ││
│  │                                                                         ││
│  │  if is_rollback == false:                                               ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ 邮件包含回滚链接 (24小时有效)                                         │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  │                                                                         ││
│  │  if is_rollback == true:                                                ││
│  │  ┌────────────────────────────────────────────────────────────────────┐ ││
│  │  │ 邮件不含回滚链接 (回滚不可逆)                                         │ ││
│  │  └────────────────────────────────────────────────────────────────────┘ ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 LTM (Long-Term Memory) 数据流

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Memory LTM Data Flow                                 │
│                                                                             │
│  Namespace: /remediation/actors/{accountId}/                                │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │                        LTM 存储结构                                  │    │
│  │                                                                     │    │
│  │  ┌──────────────────────────────────────────────────────────────┐  │    │
│  │  │ Episodes (执行记录)                                           │  │    │
│  │  │ ──────────────────────────────────────────────────────────── │  │    │
│  │  │ • 具体的修复执行案例                                           │  │    │
│  │  │ • 索引字段: intent (意图描述)                                  │  │    │
│  │  │ • 最小相关度: 0.35                                            │  │    │
│  │  │                                                               │  │    │
│  │  │ 内容:                                                         │  │    │
│  │  │ - control_id: "S3.1"                                          │  │    │

### 4.1 审批邮件生成

```
┌─────────────────────────────────────────────────────────────────────────────┐

│  │    • approve_token = sha256(task_id + "approve" + random_nonce) │        │
│  │    • reject_token = sha256(task_id + "reject" + random_nonce)   │        │
│  └─────────────────────────────────────────────────────────────────┘        │
│       │                                                                     │
│       ▼                                                                     │

│  │    • token_hash: sha256(token)                                   │        │
│  │    • task_id: uuid                                               │        │
│  │    • token_type: "approval" / "reject"                           │        │
│  │    • used: false                                                 │        │

│       │                                                                     │
│       ▼                                                                     │

│  │                                                                  │        │
